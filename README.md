# 股市观测工作台 · 云端自动刷新版

个人股票财经看板：行情（大A/港股/美股/黄金）+ 7x24 财经快讯 + 关键事件日历 + 每日盘后复盘。

**完全云端运行**：数据抓取与构建由 GitHub Actions 自动执行，产物发布到 GitHub Pages。

## 工作原理

```
GitHub Actions (cron 每10分钟，实际约 16~20 分钟一轮：GitHub 会对高频 schedule 节流)
  ├─ node _gen.js          行情：腾讯行情+天天基金净值+新浪外汇 → data.json.symbols/fx
  ├─ node _gen_news.js     快讯：新浪7x24 + 财联社 + 东财 → data.json.news / news.json
  ├─ node _gen_calendar.js 日历：东财「已定档实施」的除权除息排期（未来45天）+ 周期性宏观锚点
  │                        （LPR/PMI/非农按公布惯例滚动推算）→ data.json.calendar / calendar.json
  ├─ node _gen_review.js   复盘：盘后(北京≥15:05)抓当日盘后数据；抓不到则沿用旧复盘并打「陈旧」标记
  ├─ node _build.js        把 data.json 内嵌进 index.html
  └─ node _validate.js     校验（数值泄漏 / DOM 契约 / 死函数 / 复盘 10 模块 / 日历条目硬断言 /
                            陈旧提示一致性）
        ↓ 校验不过 → 退出码 1 → 不部署（宁停更，不部署坏产物）
提交回仓库 + 刷 jsDelivr CDN 缓存 → 官方 Pages action 发布
```

### 数据源可用性（GitHub Actions 出口 IP 的实测差异，2026-09-24 复核）

同一个接口「本机通、CI 不通」是常态，抓取层因此按可用性分层，任一层挂掉都不至于整轮作废：

| 数据 | 主源 | 兜底 | CI 实测 |
|---|---|---|---|
| 指数行情（沪/深/创业板） | 腾讯 `qt.gtimg.cn` | 东财 `push2 ulist.np` | 腾讯稳定；东财 push2 在 CI 出口 IP 上**多数轮次 http 502**（本机 63ms 正常）→ 故腾讯为主源 |
| 涨跌家数 | 东财指数字段 `f104/105/106` | 东财 `clist` 全 A 按涨幅降序**二分定位 0% 分界**再推算 | 两路都失败时该字段降级为「暂缺」，不影响其余模块 |
| 成交额 | 腾讯指数 `f37`（万元，仅累加沪+深） | 东财 `f6` | 两源交叉验证一致：16533.57 亿（创业板是深市子集，不可加入累加） |
| 除权除息排期 | 东财 `datacenter-web` `RPT_SHAREBONUS_DET` | 沿用上一轮并**剔除已过期条目** | 稳定；`PRETAX_BONUS_RMB` = 税前**每 10 股**派息（神华 22.6 / 长电 8.2 标定） |
| 估值 PE / 国债收益率 | 中证指数官网 / 中债登 | 沿用旧值 | 稳定，正常每日更新 |

前端页面内还会**实时直连**腾讯行情 JSONP（30秒~5分钟）+ 快讯 JSONP（60秒）+ 后台快照兜底，打开即最新。

### 数据陈旧可见性（重要）

复盘是「当日盘后抓取」，抓取失败时会沿用上一交易日的复盘。此时页面上 `generatedAt` 照常刷新，
**光看页头「更新于 <今天>」发现不了**——这是此前连续多日沿用旧复盘却无人察觉的机制。
现在的约定：

- `_gen_review.js` 只要「本该拿到当日数据却没拿到」就写 `review.stale.inherited = true`；
- 复盘面板顶部渲染醒目提示条，明确写出「沿用 X 的结果，不是当日数据」；
- `_validate.js` 把「数据说陈旧、页面却没提示」判为失败（反之亦然）——避免提示条被改坏后静默复发。

判「复盘是否真的在更新」的正确方式是看 `tradeDate` / `valuation.date` / `macro.date`，
**不要只看 `generatedAt`**（每轮都动），也不要只看成交额/涨跌家数（收盘后本来就恒定）。

### 两个快讯通道的差别（重要）

- **前端浏览器直连**：新浪7x24 / 财联社 / 东财，三个都能通（用户在国内的正常网络下）。
- **后台 CI 抓取**：只有新浪7x24 与东财快讯两个源**实际有数据**。财联社接口在 GitHub Actions 的机房 IP 上不可达（本机实测可达、云端连续 8 个版本缺席），因此 `news.json` 里只有两源。
  页面底部展示的是后台快照，所以条数会少于浏览器直连时的合并结果——这是正常现象，不是抓取失败。

## 目录结构

| 文件 | 作用 |
|---|---|
| `_gen.js` | 行情快照（43 个标的 + 汇率） |
| `_gen_news.js` | 多源快讯聚合（新浪/财联社/东财） |
| `_gen_calendar.js` | 财经日历：东财真实除权除息排期（未来 45 天，**每日最多 3 只主板个股 + 红利候选池全部命中**）+ 周期性宏观锚点（LPR/PMI/非农，标 est 打「约」标） |
| `_gen_review.js` | 每日复盘生成（云端模式自动抓当日盘后数据；抓不到则沿用旧复盘并打陈旧标记） |
| `_fetch_review_cloud.js` | 盘后数据抓取模块（多源分层 + 兜底，替代本地 MCP，供云端用） |
| `_build.js` | 构建 index.html |
| `_validate.js` | 校验（同时是部署闸门） |
| `_sim.js` | 本地离线自检：把 `_check.js` 里的分析函数抽出来跑一遍，扫 NaN/Inf（需先构建过，否则 SKIP） |
| `review_snapshot.json` | 当日盘后复盘的抓取缓存（同一交易日内后续轮次直接复用，避免重复抓东财） |
| `stock-dashboard/` | 站点文件（`_template.html` 模板 / `index.html` 构建产物 / `data.json` / `news.json` / `calendar.json` / `server.js` 备用链接反代） |
| `.github/workflows/refresh.yml` | 自动刷新工作流 |

## 首次部署（只需一次）

1. 把本目录推送到 GitHub 公开仓库（公开仓库 Actions 无限分钟）。
2. 仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**（不要选 Deploy from a branch）。
3. 打开 Pages 链接即可。之后自动刷新，无需任何操作。

## 数据说明

- **红涨绿跌**（A股惯例）。
- 信号 = 技术信号（均线/MACD/RSI/KDJ/布林）+ 消息修正（L1官方×1 / L2权威×0.5，L3仅浏览）。
- 复盘数据源：工作日盘后自动抓取（指数=腾讯、盘面/涨停梯队/龙虎榜/资金=东财、估值 PE=中证指数官网、国债收益率=中债登）。抓不到的字段降级显示「暂缺 / 待补」，绝不编造、也不把 `null` 拼进文案。
- 复盘"情绪阶段"是**固定规则判定**（涨停家数/炸板率/连板高度），不是 AI 实时判断。
- **财经日历的「未来事件」= 真实排期**：取自东财 `RPT_SHAREBONUS_DET` 中 `分红进度=实施分配` 的记录（仍处预案/股东大会通过阶段的记录没有登记日，天然被排除，不会再出现"把预测当结果"）。
  - 事件日期用**股权登记日**（当日收盘持有即可分红 = 最后买入日）；登记日已过则退回除权除息日，保证事件永远落在未来。
  - 清单是**精选**而非全量：单日除权高度聚集（实测单日可堆 15~16 只主板股），若只按日期取前 N 条，名额会被「今天」一天吃光，故按每日名额分摊。
  - `PRETAX_BONUS_RMB` = 税前**每 10 股**派息（标定案例：中国神华 22.6、长江电力 8.2）。
  - LPR / 官方 PMI / 美国非农按**公布惯例**推算并标 `est`（页面显示「约」），不是官方确定的日期；FOMC、CPI 等日期不规律的，宁可不放也不编。
- 估值模块只输出 PE 与其历史分位。中证 index-perf 接口没有市净率与股息率字段，页面也从未展示过，故不再输出恒为 null 的 `pb`/`div` 死字段。
- 非投资建议，市场有风险。

## 手动触发

仓库 Actions 页 → **Auto Refresh Dashboard** → Run workflow，可立即手动刷新一次。

## 本地排错

本机若 `git push` 因网络被墙失败，可改用 GitHub Contents API 逐文件 PUT（GET sha → PUT base64）；
注意每个文件一次 PUT 会各产生一个 commit，触发多个 CI run，前面的会被 `concurrency` 判 cancelled（正常）。
